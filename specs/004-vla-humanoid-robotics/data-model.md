# Data Model: Vision-Language-Action (VLA) for Humanoid Robotics

## Core Entities

### VLA System
- **Description**: The integrated system that processes natural language, perceives visual information, and executes robotic actions
- **Attributes**:
  - system_id (string): Unique identifier for the VLA system
  - status (enum): [idle, processing_voice, planning, executing, error]
  - capabilities (list): List of supported robot capabilities
- **Relationships**: Contains multiple VoiceCommands, LLM Plans, VisionDetections, and ActionExecutions

### Voice Command
- **Description**: Natural language input that triggers the VLA pipeline
- **Attributes**:
  - command_id (string): Unique identifier for the command
  - original_audio (string): Reference to audio input (conceptual)
  - transcribed_text (string): Text after ASR processing
  - timestamp (datetime): When the command was received
  - confidence_score (float): Confidence level of ASR transcription
- **Relationships**: Connected to one LLM Plan through the planning process

### LLM Plan
- **Description**: Structured task plan generated by cognitive planning
- **Attributes**:
  - plan_id (string): Unique identifier for the plan
  - original_goal (string): High-level goal from voice command
  - task_sequence (list): Ordered list of subtasks
  - safety_constraints (list): Safety checks to be validated
  - validation_status (enum): [valid, needs_revision, invalid]
- **Relationships**: Derived from one Voice Command, contains multiple Action Steps

### Vision Detection
- **Description**: Object detection and localization in the environment
- **Attributes**:
  - detection_id (string): Unique identifier for the detection
  - object_name (string): Name/class of detected object
  - bounding_box (object): Coordinates defining object location
  - confidence_score (float): Confidence level of detection
  - affordances (list): List of possible actions with this object
  - spatial_relationships (list): Relationships to other objects
- **Relationships**: Used by LLM Plan to ground tasks in visual reality

### Action Step
- **Description**: Individual action within a plan that maps to ROS 2 execution
- **Attributes**:
  - step_id (string): Unique identifier for the action step
  - action_type (enum): [navigation, perception, manipulation, communication]
  - target_object (string): Object to interact with (if applicable)
  - parameters (object): Action-specific parameters
  - execution_status (enum): [pending, executing, completed, failed]
  - error_recovery_plan (string): Fallback if action fails
- **Relationships**: Part of one LLM Plan, maps to ROS 2 Action Execution

### ROS 2 Action Execution
- **Description**: Actual execution of robot actions through ROS 2 interfaces
- **Attributes**:
  - execution_id (string): Unique identifier for execution
  - ros_action_name (string): Name of ROS 2 action interface
  - goal_parameters (object): Parameters for the ROS action
  - feedback_status (string): Current status of action execution
  - completion_time (datetime): When action was completed
- **Relationships**: Executed based on Action Step definition

### Student Learning Record
- **Description**: Tracking of student progress and understanding
- **Attributes**:
  - student_id (string): Unique identifier for the student
  - lesson_progress (object): Completion status for each lesson
  - lab_completions (list): Records of completed lab exercises
  - assessment_scores (list): Scores on comprehension assessments
  - capstone_status (enum): [not_started, in_progress, completed]
- **Relationships**: Interacts with all other entities through learning activities

## State Transitions

### VLA System States
- idle → processing_voice: When voice command is received
- processing_voice → planning: When ASR completes successfully
- planning → executing: When plan is validated and approved
- executing → idle: When all actions are completed
- [any_state] → error: When any component fails

### Action Step States
- pending → executing: When action is sent to ROS 2
- executing → completed: When action completes successfully
- executing → failed: When action encounters an error
- failed → pending: When recovery plan is initiated

## Validation Rules

1. **Voice Command Validation**:
   - Must have non-empty transcribed_text
   - Confidence score must be above threshold (0.7) for processing

2. **LLM Plan Validation**:
   - Must have at least one valid action step
   - Safety constraints must be defined
   - Task sequence must be logically ordered

3. **Vision Detection Validation**:
   - Confidence score must be above threshold (0.8) for reliable use
   - Bounding box coordinates must be within image bounds

4. **Action Step Validation**:
   - Must have valid action_type
   - Parameters must match action_type requirements
   - Must have error recovery plan for critical actions

## Relationships Summary

- VLA System → (1 to many) → Voice Commands
- Voice Command → (1 to 1) → LLM Plan
- LLM Plan → (1 to many) → Action Steps
- Vision Detection → (many to many) → Action Steps (through object references)
- Action Step → (1 to 1) → ROS 2 Action Execution
- Student Learning Record → (many to many) → All other entities (through learning interactions)
